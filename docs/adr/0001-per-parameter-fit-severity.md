# Per-parameter severity decides Fit-with-changes vs. No-fit

The supplier advisor needed a rule for turning a failed parameter check into `Fit with changes` (recoverable) vs. `No fit` (disqualifying). We considered deriving this generically from a parameter's `comparatorType`/`direction` (e.g. any threshold miss is always recoverable, any list-membership miss is always disqualifying), but rejected it: two parameters can share the same comparator shape yet have completely different real-world flexibility, and that's a business judgment the comparator's shape can't encode. Instead, `severity` (`Recoverable` | `Disqualifying`) is an explicit field set per parameter alongside its comparison rule — a supplier fails a spec `No fit` overall if any `Disqualifying` parameter fails, regardless of other `Recoverable` failures.
